# pxconv 算法说明（v3）

本文是 `pxconv.py` 的设计文档：为什么这样算、每一步的数学形式、指标怎么定义、哪里会失效。
所有数字都是本机实测（896×1152 RGBA 抠图立绘 → 128 px / 24 色，见 README「主要成果」）。

---

## 1. 问题定义

输入：$A \in [0,1]^{H \times W \times 4}$，RGBA（alpha 非二值，抠图/AI 出图后通常有几十到几百种取值）。

输出：$B \in [0,1]^{R \times C \times 4}$，其中

- $C$ = 用户给的 `--size`（输出宽度），$R = \mathrm{round}(C \cdot H / W)$；
- $B_{\cdot,\cdot,3} \in \{0, 1\}$（`hard` 模式：像素画标准，alpha 只有存在/不存在）；
- 可见像素的颜色数 $\le$ `--colors`；
- $B$ 的轮廓与 $A$ 的**真实不透明区域**一致，包括 1 px 级细结构。

三个必须解决的陷阱：

| 陷阱 | 普通做法的后果（实测） |
|---|---|
| 半透明毛边 | NEAREST 64 px 后仍留 262 个半透明像素 / 59 级 alpha；真实立绘 128 px 后 9,391 个 |
| 隐藏 RGB 渗色 | 抠图后透明区 RGB 常是黑；alpha 加权平均把黑混进边缘 → 暗边 |
| 色数爆炸 | 不做调色板收口时 24 色请求产出 197 色，palette swap 与逐像素编辑全部失效 |

## 2. 管线顺序（每一步都有存在理由）

```
读图 RGBA(float)
  └─ prepare()          : 一次建 5 通道积分图（alpha / 核心计数 / 核心RGB）   ← 可按图缓存
       └─ cells_from_sat(): 每格 覆盖率 cov、核心像素数 cnt、核心均值色 rgb   ← 每格 O(1)
            └─ on = cov ≥ cov_thr                                          ← 轮廓
                 └─ rescue_thin()  弱格且 8 邻域 ≥2 实心 → 保留            ← 细结构
            └─ fill_empty_core() 无核心像素的轮廓格 → 最近核心色扩散
       └─ alpha_mode hard → alpha ∈ {0,1}；keep → 直接用 cov
  └─ edge (none/shrink/grow)   形态学，必须在二值化之后
  └─ edge_color (avg/stretch)  边缘配色，按调色板索引操作
  └─ snap_to_palette()         收口：可见像素 ≤ --colors
  └─ despike()                 清孤立像素
  └─ trim_pad()                裁透明边 / 留白
```

**顺序铁律**

1. **二值化必须早于边缘配色**：先修色再二值化，阈值会把修好的 1 px 环切碎。
2. **边缘配色必须按调色板索引做**：写「邻居平均色」会让平均色（不在调色板里）混进输出 → 色数失控。
3. **`snap_to_palette()` 必须最后**（在 despike 之前即可）：它是色数的唯一出口。
4. **形态学在二值化之后**：对浮点 alpha 做腐蚀会造出新的半透明值。

## 3. 分数边界 + 积分图（v3 的核心）

### 3.1 为什么不能用整数分块

幼稚实现：

```python
bh, bw = h // rows, w // cols
blocks = arr[: bh * rows, : bw * cols].reshape(rows, bh, cols, bw, 4)
```

`h // rows` 的整除**向下取整**，`arr[:bh*rows]` 把余下的行**静默丢弃**。
896×1152 → 128 px 宽：`rows=165`、`bh=1152//165=6`，覆盖 $6 \times 165 = 990$ 行，**丢掉 162 行 = 14.1%**。
主体只要贴着图片底部（长裙、脚、尾巴），就会整块消失，而输出尺寸看起来完全正常。

### 3.2 积分图

把源图打包成 5 通道 $P$：

$$
P_0 = \alpha,\qquad P_1 = \mathbb{1}[\alpha \ge \tau_{core}],\qquad P_{2..4} = \mathrm{RGB}\cdot P_1
$$

累加得到积分图（含一行一列零边界）：

$$
T(y,x) = \sum_{i<y}\sum_{j<x} P(i,j), \qquad T \in \mathbb{R}^{(H+1)\times(W+1)\times 5}
$$

预处理代价 $O(5HW)$，实测 896×1152 约 **108 ms**（含读图）。

### 3.3 浮点边界的双线性求和

目标网格的格子边界是浮点坐标：

$$
y_r = \frac{rH}{R},\quad x_c = \frac{cW}{C},\qquad r=0..R,\; c=0..C
$$

对任意浮点 $(y,x)$，用 $y_0=\lfloor y\rfloor$, $r_y = y-y_0$ 做双线性插值查表：

$$
\tilde{T}(y,x) = (1-r_y)(1-r_x)T(y_0,x_0) + r_y(1-r_x)T(y_0{+}1,x_0) + (1-r_y)r_xT(y_0,x_0{+}1) + r_yr_xT(y_0{+}1,x_0{+}1)
$$

于是每格内部的通道和用四个角做容斥：

$$
S_{r,c} = \tilde T(y_{r+1},x_{c+1}) - \tilde T(y_r,x_{c+1}) - \tilde T(y_{r+1},x_c) + \tilde T(y_r,x_c)
$$

这个式子的含义是「**浮点矩形内的精确面积权重和**」——它等价于对源图做 box 覆盖积分，
但每格只要 4 次查表 + 3 次减法，与格子大小无关，且**格子严格铺满整张图**：$\sum_r\sum_c S^{(0)}_{r,c} = \sum_{i,j}\alpha_{ij}$。

> 测试 `test_fractional_grid_covers_whole_image` 断言这个恒等式误差 < 0.1%。

### 3.4 覆盖率与轮廓

格子面积 $\Delta = \frac{H}{R}\cdot\frac{W}{C}$，覆盖率

$$
\mathrm{cov}_{r,c} = \mathrm{clip}\!\left(\frac{S^{(0)}_{r,c}}{\Delta}, 0, 1\right)
$$

轮廓初始为 $\mathrm{on}_{r,c} = [\mathrm{cov} \ge \tau_{cov}]$（默认 0.5）。

### 3.5 细结构救援（hysteresis）

细线在格子里的覆盖率天然 < 阈值（1 px 线在 14×14 px 的格里只有 7%），纯阈值必然断手断腿。
救援条件：

$$
\text{keep}_{r,c} = [\tau_{cov} \cdot \eta \le \mathrm{cov}] \;\wedge\; \Big[\textstyle\sum_{8\text{-nb}} \mathrm{on} \ge 2\Big],\qquad \eta = 0.4
$$

「覆盖率够一半以上且连着身体」的细线保留；孤立噪点因为邻居 < 2 而不会被保留。
效果（真实立绘 128 px）：细结构保留率 18.2% → **77.5%**，4-连通块 7 → **1**。

### 3.6 核心像素取色

每个格子的颜色只用不透明核心像素：

$$
\mathrm{rgb}_{r,c} = \frac{S^{(2..4)}_{r,c}}{S^{(1)}_{r,c}} \quad \text{(当 } S^{(1)}_{r,c} > 0 \text{)}
$$

半透明像素（$0 < \alpha < \tau_{core}$）与透明像素**完全不参与**，因此不会把背景的隐藏 RGB 平均进来。

### 3.7 空格补色

纯边缘格 / 细线格可能一个核心像素都没有（$S^{(1)}=0$）。若直接给 0，细线会变成黑边。
处理：按 8 邻域逐层扩散，把最近的核心色填进去（最多 8 轮，**只在轮廓内补**，省掉轮廓外大量无用计算）：

$$
\mathrm{rgb}_{r,c} \leftarrow \operatorname{mean}\{\mathrm{rgb}_{r+\delta}\ |\ \delta \in \text{8-nb},\ \text{已有色}\}
$$

## 4. 调色板

### 4.1 拟合

只取核心像素（$\alpha \ge \tau_{core}$）作为样本；样本超过 12 万时用固定种子（`12345`）等距抽样 —— 结果几乎一致但快一个量级。
拟合方式：

- `median`（默认）：`PIL.Image.quantize(MEDIANCUT)`，C 实现，百万像素量级 **~20 ms**；
- `kmeans`：感知上更匀，但全量迭代在百万像素上是秒级，只作为质量对照。

调色板按 `(colors, core_thr, method)` 缓存在预处理结果里 —— 改别的参数时不重算。

### 4.2 收口（snap）

所有可见像素最后吸附到最近调色板色：

$$
\mathrm{rgb}_{r,c} \leftarrow \arg\min_{p \in \text{palette}} \|\mathrm{rgb}_{r,c} - p\|_2
$$

这是「可见色数 $\le$ `--colors`」的**唯一保证点**。边缘配色（`avg` / `stretch`）本身只允许输出
「内圈众数索引」或「内圈原色」，不能引入新色。

## 5. 指标定义（怎么验收）

| 指标 | 定义 | 适用 |
|---|---|---|
| 半透明像素数 | $\#\{\text{可见像素} \mid 0 < \alpha < 255\}$ | 像素画应为 0 |
| alpha 级数 | $\#\mathrm{unique}(\alpha)$ | 像素画应为 2（0 / 255） |
| 可见色数 | $\#\mathrm{unique}(\mathrm{RGB}_{\text{vis}})$ | 应 $\le$ `--colors` |
| **细结构保留率** | 源图中「$\alpha>0.5$ 且 9×9 邻域不透明密度 < 0.45」的像素，被输出可见格覆盖的面积占比 | **主指标**，对线稿友好 |
| 连通块数 | 输出可见掩膜的 4-连通块数 | 断肢 → 变多；整体被吃 → 变小 |
| 边缘色差 | 边缘像素色 vs 8 邻域内圈像素色的平均 L1 距离（×255，0~441） | **仅对无描边图像可信**（见 §7） |
| 覆盖率守恒 | $\sum S^{(0)}_{r,c}$ vs $\sum \alpha_{ij}$ | 抓「图被裁掉」这类结构性 bug |

## 6. 复杂度

| 阶段 | 代价 | 实测（896×1152） |
|---|---|---|
| 读图 + 建积分图 | $O(5HW)$ | 108 ms |
| 每格覆盖率/取色 | $O(1)$/格 → $O(RC)$，与源图大小无关 | 全流程 20 ms（128 px） |
| 细结构救援 | $O(9RC)$ | 含在上面 |
| 调色板拟合（median） | $O(\text{样本量})$ + C 实现 | ~20 ms（按图缓存） |
| 收口 | $O(RC \cdot K)$ | 含在上面 |
| 内存 | $5 \cdot 4 \cdot HW$ 字节 | 896×1152 ≈ 21 MB |

改参数（积分图与调色板都命中缓存）：**18 ms** —— 这是 UI 能实时拖滑块的原因。

## 7. 已知失效场景

1. **边缘色差指标在线稿图上失真**：角色自带黑描边时「边缘色 ≠ 内圈色」是设计意图而非渗色；
   把线稿糊掉的算法反而得分低。→ 用细结构保留率 + 连通块 + 肉眼。
2. **`shrink` 在极小输出尺寸会削断细结构**：1 px 宽的手臂被腐蚀掉后，边缘色差跳到 50+（是参考失真，不是渗色）。
3. **`keep` 模式不是像素画**：保留 cov 渐变 → alpha 有上百种取值（示例 64 px 下 1,359 个半透明像素）。
4. **真·柔内容**（烟雾、半透明阴影、发光）硬边化必然损失，这是方法不适用，不是 bug。
5. **不做放大**：预览放大是 NEAREST，不生成新信息。
6. **动画多帧共用调色板需自己负责**：本工具按单张图拟合，逐帧独立拟合会导致播放闪烁。
7. **超大图内存**：积分图是 5 通道 float32，4K 图约 160 MB，需切分处理。

## 8. 参数敏感性（示例图 256×320 → 64 px / 16 色）

| 参数 | 变化 | 观察到的效果 |
|---|---|---|
| `--cov-thr` 0.5 → 0.65 | 轮廓瘦一圈 | 边缘像素 308 → 302，视觉上细线更细 |
| `--edge shrink` | 腐蚀 1 px | 边缘像素 308 → 237（-23%），去光晕有效，但小图上细结构危险 |
| `--edge-color avg` | 内圈众数色 | 边缘色差 2.3 → 1.1（示例图），但发灰率 0.55 → 0.75（把描边染色了） |
| `--edge-color stretch` | 内圈原色外推 | 边缘色差 2.3 → 1.7；轮廓色整体靠近内圈 |
| `--rescue off` | 关细结构救援 | 细结构保留率 94.7% → 67.1% |
| `--core-thr` 0.7 → 0.9 | 只取更实的像素 | 细线格更容易落入「无核心像素」分支，靠空格补色 |
| `--colors 16 → 8` | 更少颜色 | 8 色在示例图上仍达标（≤8），但写实图会明显脏 |
